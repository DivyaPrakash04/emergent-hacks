# CLAUDE.md

Roomsure: a hackathon web app for finding a 1–6 month room you can trust. Judged on functionality, usability, technical execution and originality; the live demo is 2 minutes.

**Start with [handoff.md](handoff.md)**: current state, next steps in order, and gotchas. Product behavior lives in the MVP requirements doc, structure in ARCHITECTURE.md, and the stage path in demo-script.md.

## Layout

- `website/`: the UI (Lovable export, TanStack Start). All data goes through `src/lib/roomsure/api.ts` → `/api` on the backend, with mock fallback. Follow `website/AGENTS.md` for UI rules.
- `platform/`: the backend (Next.js 16, SQLite, demo-mode payments). Routes live in `app/api/[...path]/route.ts`; the Claude adapter is in `lib/ai/`; shared logic is in `lib/roomsure/`; the eval is in `evals/`.
- `ranking/`: engine docs and the offline `demo.html` (generated by `node ranking/build-demo.mjs`).
- `roomwalk/`: 3D viewer and the scan pipeline.

## Rules

- Scores, prices and scam verdicts come from code, never from Claude or UI code.
- Keep the honesty labels: "Demo data", "Simulated", "Sample 3D scan · demo", "Outside · not verified by Roomsure", "Read by Claude" / "Read by rules (offline)".
- No real ID, card or payment fields. Keep `PROVIDER_MODE=demo`.
- Run the tests before pushing: `cd platform && npm test && npm run test:e2e`; `cd website && npx vitest run && npx tsc --noEmit`; `node --test ranking/rankListings.test.ts`.
- Before pushing from David's Mac, check `gh auth status`.
- Don't pass `--approve-harness` to the eval runner on your own; a person approves eval changes.
- Never put API keys in chat or in git.
- Keep the docs in sync when you change behavior, routes or data.
